      How a scan works

      1. Resolve dependencies

        Reads exact versions from your lockfile, or compiles them. No version is guessed.

        Lockfile · uv

      2. Find known advisories

        Looks up each exact version in the open vulnerability database.

        OSV

      3. Research the function

        Finds which function each advisory affects, and keeps the source links.

        Tavily

      4. Index your code

        Builds a static index of imports and calls from the source text. Your code is read, never run.

        Static analysis

      5. Reason over the evidence

        The model works through the index with tool calls. A claim with no call path in the index becomes uncertain.

        Nemotron

      6. Rank and write verdicts

        Likely reachable first, then uncertain, then no reachable path detected.

        Verdict rules

      Three verdicts

      likely reachable
      A call path from the repository’s own code to the vulnerable function was found, with file and line.
      uncertain
      The evidence was missing or a step failed. It is never counted as a pass.
      no reachable path detected
      No path was found within the scope stated for that finding. It is not proof of safety.

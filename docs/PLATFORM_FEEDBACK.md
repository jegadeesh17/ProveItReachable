# Platform feedback log

A running log of friction and wins with Nebius Token Factory, Sandboxes and Nemotron, written while building ProveItReachable. Each entry: date, area, what happened, impact, suggestion. This feeds the Devpost platform-feedback field.

| Date | Area | What happened | Impact | Suggestion |
|---|---|---|---|---|
| 2026-10-24 | Docs: function calling | The function-calling guide uses only a Llama 3.1 8B model in its examples and has no table of which models support `tools` / `tool_choice`. No Nemotron model is mentioned, and parallel tool calls are not covered. | We had to rely on third-party listings for Nemotron model IDs and schedule a spike just to confirm tool calling works. | Add a per-model capability matrix (tools, parallel tool calls, JSON mode, context length) and a Nemotron function-calling example. |
| 2026-10-24 | Docs: Sandboxes Python quickstart | The quickstart shows `images.use()` + `run()` but no complete create → upload files → run → read results → clean up script, and no upload example. | Extra discovery time to work out the lifecycle for "upload a repo, then run analysis offline". | Add one end-to-end script covering upload, networked setup, saving an image, an offline run, and cleanup. |
| 2026-10-24 | Docs: Sandboxes auth | The SDK needs `NEBIUS_PROJECT_ID`, while the CLI uses `NEBIUS_AI_PROJECT`, and the docs warn that one does not replace the other. | An easy misconfiguration for anyone using both the SDK and the CLI. | Accept one variable name across the SDK and CLI, or have the SDK error message name the variable it expected. |
| 2026-10-24 | Docs: Sandboxes limits and pricing | The limits page gives no CPU, memory, file-upload or maximum-timeout numbers (you are told to query `/whoami` or email the team) and nothing on pricing or whether free credits cover Sandboxes. | Spend-cap sizing for a demo that must stay up for 7 weeks is guesswork until usage is observed. | Publish default limits and per-unit Sandbox pricing, and state whether promotional credits apply. |
| 2026-10-24 | Sandboxes SDK: no networking control | `contree-sdk` 0.3.6 `run()` has no networking parameter (nor `uid`/`gid`); the REST `POST /sandboxes/v1/instances` body has `networking.enabled` and `uid`/`gid`. | Offline, non-root execution needs a raw REST call beside the SDK. | Expose `networking`, `uid` and `gid` on the SDK `run()`, matching the REST API. |
| 2026-10-24 | Sandboxes: access | With a fresh hackathon account, `/sandboxes/v1/whoami` returns 200 with limits populated, but every permission (`import`, `spawn`, `spawn_disposable`, `list`, `cancel`, `set_image_tag`) is `false`; spawning returns `403 You do not have permission to perform this action`. Nothing in the console onboarding said Sandboxes needed separate activation. | Blocks the hackathon's own Coding-track brief ("tools that operate within Token Factory Sandboxes") on day one. | Activate Sandboxes automatically for hackathon/Builder Program projects, or show an "Activate Sandboxes" step in the console, and make the 403 message say which permission is missing and how to get it. |
| 2026-10-24 | Sandboxes: beta gating | The cause of the 403 was that Sandboxes are a beta that needs a "Request beta access" form on the console's Sandboxes page. Neither the 403 body, `whoami`, nor the docs' access-setup page mention the form (the docs point to emailing contree@nebius.com instead), so we emailed before finding the console button. The console page also says beta runs are free and not to process personal or sensitive data. | Two support channels used for one request; time lost diagnosing. | Return a 403 message like "Sandboxes beta access required: request it at <console link>", and put the same link in the access-setup docs. |
| 2026-10-24 | Inference (win) | Nemotron 3 Super 120B: chat in 0.7 s, OpenAI-style tool calling worked on the first try (`auto` and forced `tool_choice`), JSON mode worked, and `usage` (including `reasoning_tokens`) is returned. | Our tool-calling design works as planned; no JSON-loop fallback needed. | Document this in the function-calling guide; it is a strong result. |
| 2026-10-24 | Inference: output format | Responses from the reasoning Nemotron models start with leading newlines (`"\n\nOK"`), and one reply had an unusual character in place of an em dash. | Minor: clients must strip/normalize output. | Note the behaviour in the model card. |
| 2026-10-24 | Docs: Sandboxes networking (win) | Disabling networking per operation (`networking.enabled=false`) and the documented pattern "fetch deps with network, save an image, verify offline" fit our safety model exactly. | This lets us run untrusted repo code without network access, which is the core safety guarantee. | Promote this pattern on the Sandboxes overview page; it is a strong selling point for security tooling. |
